## 当前仓库状态

对比 `v1.10`，当前仓库已经把《后续工作计划》里第一批最关键的内容基本落地了：

1. 已有第一版原生 `插电保持`，会围绕“停止充电”目标电量做小范围补电。
2. 已有 `保持带宽`，可以决定掉到目标下方多少再开始补电。
3. 已有四档 `保持策略`：`平衡 / 偏向外接供电 / 偏向减少循环 / 智能自适应`。
4. `智能自适应` 已经做成第一版规则型实现，会根据近几次平均电流、温度、适配器功率、无线充场景在 runtime 自动切换实际生效策略。
5. 已有 `系统优化充电` 协调逻辑，支持永久停用，或仅在保持/停充阶段临时停用，并会记录接管前原始状态与协调会话；daemon 重启后也会优先按当前真实电池快照重新评估，再决定恢复还是继续接管。
6. 已有单独的 `策略诊断` 页面，可以看到策略原因、切换历史、充电命令时间、禁流时间、自适应负载等级、当前生效策略，以及 Smart Charge 接管前状态和接管开始时间等运行时信息；现在还会把最近一段策略事件时间线写入独立 `sqlite` 事件表，并支持复制摘要、导出事件时间线，以及复制真机长测校准模板。
7. 主页面已增加 `电源路径/策略状态` 卡片，直接展示当前守护状态和保持范围。
8. `历史统计` 页面现在也开始整合策略事件，并且会通过独立事件接口从 `sqlite` 事件表读取数据，按当前分页时间范围显示对应的策略事件时间线；事件类型也已细分到 `状态 / 保持 / 接管 / 温控 / 保持策略运行时切换` 这一层。
9. 已有 `满充计划`，可以定期在指定时间临时解除电量上限。

需要先说明的一点仍然没变：

**它现在仍然不是硬件级旁路充电。**

当前实现依然是软件层决定“什么时候停充、什么时候恢复补电、什么时候协调系统优化充电”，只是比以前更接近长期插电驻留体验。

## 相对上次提交，这一轮具体改进了什么

相对上次提交 `0137d41 / v1.10新增 满充计划 功能`，这一轮主要补了下面几类能力：

1. `插电保持` 从“只有停充”升级成了“停在目标附近的小范围补电”
   作用：
   让设备插着电时，不是一路充到更高电量，而是尽量停留在你设定的目标附近。
   这次补上的内容：
   `保持带宽`、`平衡 / 偏向外接供电 / 偏向减少循环 / 智能自适应` 四档策略，以及运行时自动切换的第一版自适应逻辑。
   资源开销：
   会增加一点点后台轮询和电流样本计算开销，因为 daemon 需要周期性判断是否该补电、该切哪档策略。
   结论：
   这是小幅增加运行时开销，换来更稳定的长期插电体验。

2. `系统优化充电` 协调从“简单开关”升级成了“可追踪、可恢复的接管逻辑”
   作用：
   避免 iOS 自己的优化充电和 ChargeLimiter 的停充/保持策略互相打架。
   这次补上的内容：
   接管前原始状态、协调会话、启动后按真实快照重算再恢复、以及“接管会话已释放”事件。
   资源开销：
   基本只在状态切换、daemon 启动或配置切换时额外做几次判断，不是高频常驻任务。
   结论：
   运行时开销几乎可以忽略，主要提升的是稳定性和可恢复性。

3. 新增了完整的 `策略诊断` 与导出能力
   作用：
   把“为什么停充、为什么补电、为什么 Smart Charge 被接管”直接展示出来，排障不再靠猜。
   这次补上的内容：
   诊断页、事件时间线、`复制诊断摘要`、`导出事件时间线`、`复制长测校准模板`。
   资源开销：
   这些大多是按需打开、按需导出的 UI 和文本能力，平时不点基本没有额外负担。
   结论：
   常驻开销很小，主要是用户操作时才消耗一点 UI 和文本处理资源。

4. 策略事件现在会持久化到独立 `sqlite` 表，并整合进历史页
   作用：
   让“这一段曲线为什么这样走”可以直接对上当时发生的状态切换、保持补电、Smart Charge 接管和温控事件。
   这次补上的内容：
   独立 `policy_events` 表、专用 `get_policy_events` 接口、历史页时间线、基础筛选、事件类型细分。
   资源开销：
   会增加少量 `sqlite` 写入和一点点磁盘占用，因为每次关键策略切换都会记事件。
   结论：
   这是小幅增加存储和 I/O 开销，但收益是长时间复盘能力大幅提升。

5. 增加了真机长测与阈值校准支撑
   作用：
   让后面调 `保持带宽 / 保持策略 / 温控阈值 / Smart Charge 恢复行为` 时，有统一的记录模板和验证流程。
   这次补上的内容：
   `复制长测校准模板` 按钮和 `docs/真机长测与阈值校准.md`。
   资源开销：
   几乎没有运行时开销，本质上是导出文本和文档补充。
   结论：
   这部分基本不增加常驻资源消耗。

6. 构建和打包链路做了收尾清理
   作用：
   让发布包生成更稳定，工作区更干净，直接 `xcodebuild` 时日志也更容易看。
   这次补上的内容：
   `scripts/build_packages.sh` 改为临时 staging 打包、自动读取 `MARKETING_VERSION`、关闭默认 MonkeyDev 自动打包/安装、清理 `/opt/lib` 搜索路径警告、重写 `构建安装包.md`。
   资源开销：
   这部分不增加 App 运行时开销；只是在打包时会额外用一份临时目录，构建阶段会多一点磁盘占用。
   结论：
   对用户运行时几乎没有影响，主要改善开发和发版体验。

## 资源开销总结

- 日常运行时，真正会增加一点常驻开销的，主要是 `插电保持 / 智能自适应` 的轮询判断，以及策略切换时写入 `sqlite` 事件。
- 这些开销整体都属于“小幅增加”，不是重型后台任务；相比收益，更像是用少量后台判断换来更稳定的充电控制和更强的可观测性。
- `策略诊断`、`导出按钮`、`长测模板`、`构建脚本整理` 这几类改进，基本不会增加平时的运行时资源消耗。
- 如果你不开 `插电保持`、不看诊断页、也不导出事件，那么这部分新增能力对日常资源占用的影响会更小。

## 功能与按键完整说明

下面按页面把当前新增和增强过的按键、选项、入口、状态项全部写清楚，方便直接给用户看。

### 高级设置 -> 加速充电

- `加速充电`：这是一个入口，不会直接改电池上限。进入后可以临时关闭部分高耗电功能，让设备在充电期间自身耗电更低，从而把更多输入功率留给电池。适合着急回电时使用。
- `飞行模式 / 关闭 WiFi / 关闭蓝牙 / 降低亮度 / 低电量模式`：这些是加速充电子项。它们调整的是设备当前的系统状态，不是充电芯片本身。作用是减少边充边耗，提升体感回电速度。

### 高级设置 -> 停充控制

- `智能停充`：使用系统的 SmartBattery API 参与停充控制。它调整的是“软件告诉系统是否继续充电”的方式，不是硬切断物理供电。适合希望停充动作更贴近系统层行为的场景。
- `停充时启用禁流`：当达到停充条件后，不只是停止给电池充电，还尽量阻止电流继续流入设备，让机器更多依赖电池放电维持当前负载。这个选项更激进，适合少量特殊场景，但不建议和 `插电保持` 一起常开，因为两者思路相反。
- `插电保持`：把“停止充电”目标当作保持目标。达到目标时先停充，掉到目标下方一小段范围后再自动补电，尽量让电量长时间停在目标附近。它解决的是“我想插着电用，但不想一路慢慢冲到 100%”这个问题。
- `保持带宽`：决定目标电量下方允许回落多少再恢复补电，范围是 `1% ~ 10%`。例如目标是 `50%`，带宽是 `2%`，则大致会在 `48% - 50%` 区间内工作。带宽越小，电量越贴近目标，但可能更频繁补电；带宽越大，补电次数更少，但电量波动会更明显。
- `保持策略`：这个选项不会改变你的目标电量，只会改变 hold 模式下 daemon 的观察节奏、提前补电积极程度，以及在自适应模式下允许的自动切换逻辑。
- `平衡`：默认建议选这个。大约每 `15` 秒检查一次 hold 状态；如果设备已经处在保持范围内，但连续 `2` 次都明显在放电，就会提前开始补电。它追求的是“体验稳定”和“减少小循环”之间的折中。
- `偏向外接供电`：最积极的一档。大约每 `10` 秒检查一次，而且只要连续 `1` 次明显持续放电，就可以提前补电。适合游戏、导航、热点、高亮度看片这类持续高负载场景，目标是尽量不要让电量明显往下掉。
- `偏向减少循环`：最保守的一档。大约每 `20` 秒检查一次，并且默认关闭“持续放电后提前补电”。它更愿意等电量真正掉到保持下边界再恢复补电，适合轻负载、长期插电挂机的场景。
- `智能自适应`：这是当前第一版真正会自动切换的保持策略。它会结合近几次平均电流、当前温度、适配器功率、是否无线充，自动在 `偏向外接供电 / 平衡 / 偏向减少循环` 之间切换运行时策略。
- `智能自适应` 在 `低负载` 时更偏向 `偏向减少循环`：也就是尽量少补电，减少目标附近的小幅来回。
- `智能自适应` 在 `中负载` 时更偏向 `平衡`：避免电量缓慢下滑太明显，同时也不过度频繁补电。
- `智能自适应` 在 `高负载 + 适配器功率足够` 时更偏向 `偏向外接供电`：会更积极地提前补电，减少用户看到电量往下掉的速度。
- `智能自适应` 在 `温度接近上限` 时会进入更保守的 `温控保护`，在 `无线充` 时也会走更保守的 `无线充保护`，避免在更敏感的供电环境下来回抖动。
- `智能自适应` 还加了最小驻留时间和分级滞后，不会因为一两次电流波动就来回切策略。它解决的是“同一台机器在不同负载场景下，其实不适合同一套固定保持参数”的问题。

### 高级设置 -> 系统优化充电

- `永久停用系统优化充电`：直接关闭 iOS 自带的优化充电策略，避免系统自己的充电调度和 ChargeLimiter 打架。适合本来就不想用系统优化充电、只想完全按 ChargeLimiter 逻辑工作的用户。它改变的是更长期的系统行为，不只是当前这一次插电。
- `插电保持时临时停用`：只在进入 `保持 / 停充 / 温控暂停 / 禁流` 等状态时，临时停用系统优化充电；退出这些状态后再尝试恢复。现在 daemon 会在进入接管前记录系统原始状态，并给这一轮接管打上会话标记；如果 daemon 在中途重启，会先按当前真实电池快照重算一遍策略，再决定这次该恢复还是继续保持接管，尽量避免把仍在接管窗口内的状态过早恢复。如果系统状态已经被别的动作改掉，历史页里也会记录“接管会话已释放”这一类事件，方便排查竞态。

### 高级设置 -> 调试与观测

- `策略诊断`：这是一个查看页入口，不会直接改充电行为。它的作用是把“当前为什么停充、为什么补电、为什么系统优化充电被接管”这些问题直接展示出来，避免只能靠猜。
- `守护策略`：显示 daemon 当前处于什么状态，比如 `插电保持中`、`插电保持中 · 补电`、`已连接电源 · 停止充电`、`温控暂停充电`、`停充时已禁流`。
- `当前状态原因`：告诉你这一步是因为到达保持目标、低于保持下边界、持续放电趋势、高温、低电量保护，还是其他条件触发的。
- `最近策略切换时间 / 最近策略切换原因`：用来回看最近一次状态切换到底发生在什么时候、为什么发生。
- `充电命令 / 最近充电命令时间`：显示 daemon 现在是在允许充电还是保持停止，以及最近一次下发开始充电或停止充电命令的时间。
- `系统停充抑制 / 系统优化充电 / 由本工具接管 / 最近禁流恢复时间`：这一组用来区分到底是系统原生逻辑在生效，还是 ChargeLimiter 临时接管了相关行为。
- `接管前系统状态 / 协调会话 / 接管开始时间`：这一组专门对应 Smart Charge 协调增强。它可以帮助判断这次临时停用前系统本来是什么状态、这是哪一次接管会话、以及这轮接管从什么时候开始。
- `保持策略`：显示你在设置页里选择的配置策略。
- `当前生效策略`：显示当前 runtime 里实际正在用的策略。这个字段在 `智能自适应` 下尤其重要，因为你选的是“自动”，但真正生效的可能是 `偏向外接供电`、`平衡` 或 `偏向减少循环` 其中之一。
- `自适应负载等级`：显示 daemon 当前把场景判定成了 `低负载 / 中负载 / 高负载 / 温控保护 / 无线充保护 / 固定策略` 中的哪一类。
- `近几次平均电流`：显示自适应逻辑最近几次采样后的平均电流，方便理解为什么当前会被判成高负载还是低负载。
- `保持目标 / 保持带宽 / 保持下边界 / 持续放电计数 / 轮询间隔 / 提前补电辅助`：这一组专门用来解释 hold 模式内部行为。你可以直接看到当前目标区间、连续放电次数、多久轮询一次，以及当前是否允许“提前补电”。
- `当前电量 / 电池温度 / 电池电流 / 瞬时电流 / 是否正在充电 / 是否连接外部电源 / 系统判定可充电`：这些是策略判断时最直接的实时信号。
- `适配器 / 适配器功率 / 充电方式`：用来帮助判断当前外部供电环境，例如有线还是无线，功率够不够高。
- `最近若干次状态变化`：会列出 daemon 运行期间最近几次状态切换，方便回看 hold 和补电是怎么来回变化的。
- `长时间事件时间线 / 最近持久化策略事件`：这是这次继续优化后新增的一组诊断内容。它会把最近一段时间的策略切换连同当时的电量、电流、温度等快照一起写进独立 `sqlite` 事件表，并保留一份本地 runtime 镜像作为兜底；即使 daemon 中途重启，这段时间线也会尽量保留。它解决的是“短时间窗口看得到，但隔一会儿就丢了，没法复盘”的问题。
- `复制诊断摘要`：这是策略诊断页里新增的操作按钮。按下后会把当前守护状态、保持策略、Smart Charge 接管信息，以及最近一段持久化策略事件整理成一段文本并复制到剪贴板。适合用户反馈问题、远程排查、或者你自己存档对比不同机型表现时使用。
- `导出事件时间线`：这是策略诊断页里新增的导出按钮。它会调起系统分享面板，把最近持久化的策略事件时间线导出成文本，方便发给别人、存到备忘录、保存到文件或继续做人工分析。它调整的不是策略本身，而是“复盘与协作排障”的效率。
- `复制长测校准模板`：这是这次为了真机长时间验证补上的按钮。按下后会把当前机型、系统版本、关键保持参数、Smart Charge 状态和一组建议验证项整理成模板并复制到剪贴板。它不改变策略本身，作用是把“真机长跑记录、阈值校准、远程协作复盘”标准化，避免每次都手写测试背景。

### 高级设置 -> 满充计划

- `启用满充计划`：开启后，设备会按你设定的节奏，周期性进入一次“临时放开上限”的满充窗口。它调整的是电量上限策略，不影响温度保护。
- `每隔天数`：决定多久触发一次满充窗口。例如设成 `7`，就是每 `7` 天执行一次。
- `开始时间`：决定满充窗口在一天中的哪个时间点开始。适合安排在夜间、睡前、出门前这类固定时段。
- `持续时长`：决定这次临时放开上限要持续多久。时间越长，更容易真正充到更高电量；时间越短，则更偏向轻量校准。

### 高级设置 -> 限流控制

- `限流等级`：通过高温模拟来压低充电电流。选择 `关闭` 时不启用自动限流，其他等级越高，充电电流通常越小。这个选项调整的是充电速度和发热平衡，适合发热大或边充边用的场景。

### 高级设置 -> 高温模拟 (Powercuff)

- `默认等级`：决定非充电状态下的高温模拟等级。等级越高，系统会更偏向保守性能和功耗。
- `锁定等级`：防止系统自动调整高温模拟等级，强制维持你手动设定的档位。适合测试或需要固定策略的场景。

### 高级设置 -> 其他

- `重置所有设置`：把 ChargeLimiter 的当前配置恢复到默认值。适合排查异常、重来一遍，或者在尝试过很多参数后快速回到初始状态。

### 主页面新增状态展示

这一部分不是按钮，但它们是判断 ChargeLimiter 当前到底在干什么的第一观察入口：

- `守护策略`：当前策略状态总览。
- `充电命令`：现在到底是允许充电还是保持停止。
- `系统停充抑制`：系统层停充抑制是否真的生效。
- `系统优化充电`：当前是系统原生状态，还是被 ChargeLimiter 临时接管。
- `保持策略`：当前配置的 hold 策略；如果你选的是 `智能自适应`，这里会额外显示当前偏向哪一档。
- `保持范围`：当前实际工作的 hold 区间，例如 `48% - 50%`。

### 历史统计页面

- `策略事件时间线`：这是继续执行工作计划后加进历史页的新卡片。它会通过独立的策略事件接口，从 `sqlite` 事件表里把当前历史图表分页对应时间范围内的策略事件筛出来，方便把“这一段电量曲线怎么波动”与“这一段到底发生了什么策略切换”直接对上。
- `全部`：显示当前页时间范围内的全部策略事件。适合第一次看历史页时先做全局复盘，快速知道这一段时间到底发生过哪些切换。
- `状态`：只看通用状态变化事件，例如普通充电/停充切换、插拔电源后的状态变化、满充窗口导致的状态变化。它适合回答“这一段时间电量曲线为什么切到了另一个状态”。
- `保持`：只看 `插电保持` 相关事件，包括达到保持目标、保持补电、提前补电，以及自适应模式下当前生效保持策略的运行时切换。它适合专门分析 hold 模式到底有没有按预期工作。
- `接管`：只看 `系统优化充电` 协调事件，例如什么时候被临时停用、什么时候恢复、什么时候因为当前配置被永久关闭。它适合排查系统优化充电和 ChargeLimiter 是否打架。
- `温控`：只看高温停充与降温恢复事件。它适合分析某一段异常停充到底是电量阈值导致，还是温控保护导致。
- `策略事件时间线` 在当前页有命中事件时：会优先显示这一页时间范围内的事件，而不是简单显示全局最新事件。它解决的是“看图表是一页，看事件是另一页，时间对不上”的问题。
- `策略事件时间线` 在当前页没有命中事件时：会自动回退显示最近几条持久化策略事件，并明确告诉你这是回退结果。这里的“最近事件”同样优先来自独立 `sqlite` 事件表，只有在事件表暂时不可用时才退回 runtime 镜像。这样历史页不会空白，你也能立刻知道最近系统发生过哪些策略变化。
- 每条策略事件都会显示：发生时间、事件分类标签、状态切换或接管动作、触发原因，以及当时的电量、电流、温度等关键快照。它的价值是让历史页不再只有曲线，也有“为什么变成这样”的上下文。

### 使用建议

- `插电保持` 不建议和 `停充时启用禁流` 一起常开。前者的目标是在目标附近小范围补电，后者的目标则是尽量不让电流流入，两者思路相反。
- 如果你想要“更像电脑那样插着电慢慢守在某个电量附近”，优先尝试 `插电保持 + 保持带宽 + 保持策略` 这一组。
- 如果你长期固定插电玩轻负载内容，可以先从 `偏向减少循环` 或 `智能自适应` 开始。
- 如果你经常游戏、导航、热点、录屏，可以先试 `偏向外接供电` 或 `智能自适应`。
- 如果你发现状态不符合预期，先看主页面状态卡，再进 `策略诊断`，基本就能知道当前为什么停充、为什么恢复补电、为什么切了策略。
- 如果你想把现场信息发给别人一起分析，优先使用 `复制诊断摘要` 或 `导出事件时间线`，这样比手动截图更完整，也更容易看出长时间策略变化。
- 如果你想研究“某一段历史曲线为什么会掉电、补电、停充”，可以直接进 `历史统计` 页面看对应分页下方的 `策略事件时间线`，它比只看图更容易对上原因。

## 📦 构建安装包 (快速上手)

详细步骤与踩坑说明请看仓库根目录的 `构建安装包.md`，真机验证建议看 `docs/真机长测与阈值校准.md`。

软件要求: **Xcode**, **xcode-select (CLI tools)**, **dpkg-deb** (brew install dpkg)。

```bash
# 推荐：自动读取 MARKETING_VERSION，统一生成 TrollStore / rootless / roothide
./scripts/build_packages.sh

# 可选：手动指定版本号
./scripts/build_packages.sh 1.10.1
```

这个脚本现在会先在临时目录准备打包树，再生成 deb，因此不会再把构建产物直接写回仓库里的 `Package_rootless` / `Package_roothide`，日常发版时工作区会干净很多。
