# ChargeLimiter

一个面向 iPhone 的充电控制工具，目标是让设备更少地长时间停留在高电量、高温和无意义满充状态，同时保留日常可用性。

> 先说结论：它不是硬件级旁路充电。
>
> 当前实现仍然是软件层策略控制。它会结合电量、温度、外部供电状态、系统优化充电状态和守护进程逻辑，决定什么时候停充、什么时候恢复补电、什么时候临时协调系统优化充电。

## 适合谁

- 你希望 iPhone 长期插电时，不要一路慢慢充到 100%
- 你希望把设备长期保持在一个更低、更稳定的电量区间
- 你经常边充边用，想更清楚地知道“现在到底为什么停充 / 补电 / 限流”
- 你愿意在“续航上限、温度、性能、充电速度”之间自己做取舍

## 核心能力

- 电量上限 / 下限控制
- `插电即充` 与 `边缘触发` 两种基础充电模式
- 温度控制
- `插电保持`：围绕目标电量小范围补电
- 四档保持策略：`平衡 / 偏向外接供电 / 偏向减少循环 / 智能自适应`
- 系统优化充电（Smart Charge / Optimized Battery Charging）协调
- 满充计划：定时临时解除电量上限
- 限流控制与 Powercuff 高温模拟
- 策略诊断、事件时间线、导出摘要与长测模板

## 项目定位

ChargeLimiter 更像一个“充电策略调度器”，而不是“硬件电源路径改造器”。

它做的事，是根据你设定的规则和当前电池状态，决定：

- 允许继续充电
- 暂停充电
- 禁止电流继续流入设备
- 在目标电量附近恢复一小段补电
- 在特定状态下临时接管系统优化充电
- 在定时窗口内暂时放开上限

它不做的事，是把 iPhone 真正改造成安卓游戏手机上那种硬件旁路供电。

## 快速上手

### 1. 最常见的保电量方案

如果你只是想“像笔记本那样长期插电，但尽量别总是 100%”：

1. 把 `停止充电` 设到你想长期停留的电量，例如 `50% ~ 80%`
2. 打开 `插电保持`
3. `保持带宽` 先从 `2%` 开始
4. `保持策略` 先选 `平衡`，不确定就选 `智能自适应`
5. 打开 `插电保持时临时停用系统优化充电`

这是最适合大多数人的起点。

### 2. 两种基础充电模式

#### 插电即充

- 插上电源后，如果当前电量低于上限，就开始充电
- 达到上限后停止充电
- 更接近日常人的直觉：插上就充，到点就停

适合：

- 日常使用
- 临时补电
- 不想研究太多阈值关系的用户

#### 边缘触发

- 插上电源后，不会因为“刚插上”就立刻开始充
- 只有当电量掉到 `开始充电 (电量 ≤)` 设定值以下时才恢复
- 达到 `停止充电 (电量 ≥)` 后再停

它本质上是一套更明显的“回差控制”。

适合：

- 想减少频繁启停
- 想让电量在一段区间内自然波动

举例：

- `开始充电 = 45%`
- `停止充电 = 50%`

那么设备会更像一个带回差的温控器：

- 到 `50%` 停
- 掉到 `45%` 才重新开始

补充说明：

- 如果你把 `停止充电` 设为 `100%`，ChargeLimiter 会把“电量上限控制”交回系统
- 这时更像“只保留温度相关保护，不再主动做电量上限干预”

## 使用时需要知道的几个事实

### 1. 电池老化和什么关系最大

Apple 官方对 iPhone 电池寿命的说明里，明确把 `温度历史` 和 `充电模式` 视为影响化学老化的重要因素；Apple 也明确说明优化充电的目标之一，是减少 iPhone 长时间处于满电状态的时间。[参考资料](#参考资料与依据)

### 2. 为什么“插电保持”不是毫无波动地钉死在一个数字

因为真实电池和系统充电状态本来就存在采样、滞后和安全策略。Apple 自己的 `Charge Limit` 也不是“到 80% 就永远一动不动”，而是会在连接电源期间掉出一小段后再恢复充电。ChargeLimiter 的 `保持带宽` 做的，其实就是把这个“回差”交给你自己调。

### 3. 为什么高温要优先看

Apple 明确说明：高温会永久缩短电池寿命；设备过热时，系统甚至会降低或停止充电。对长期插电用户来说，“电量太高”和“温度太高”通常都比“少补了 1% 电”更值得优先关注。[参考资料](#参考资料与依据)

## 高级设置详解

下面按 `充电高级` 页面顺序，逐项解释。

---

### 加速充电

`加速充电` 不是去提高充电器的输出功率，而是尽量减少设备自己正在消耗的功率，让更多输入功率留给电池。

这部分更像“给手机减负”，不是“给充电器超频”。

| 选项 | 它实际做什么 | 适合什么时候开 | 资源开销 / 代价 |
| --- | --- | --- | --- |
| `启用加速充电` | 作为总开关，在需要开始充电时自动应用你勾选的子项，停止充电或拔线后再恢复 | 临时快速补电 | daemon 开销几乎可以忽略，主要代价是可用性变化 |
| `飞行模式` | 尽量关闭蜂窝相关无线活动 | 地铁、出门前、信号差环境下急充 | 通知、电话、蜂窝数据会受影响；收益通常也是这里面最大的之一 |
| `关闭 WiFi` | 关闭 Wi-Fi 无线活动 | 你确定这段时间不用网，或当前正在频繁联网 | Apple 也说明 Wi-Fi 在未连接时本来就很省电，所以“没在用网”时收益未必大 |
| `关闭蓝牙` | 关闭蓝牙与外设连接 | 没连耳机、手表、车机、手柄时 | 会影响蓝牙配件；如果本来就没连东西，收益通常有限 |
| `降低亮度` | 将亮度拉低，并在需要时关闭自动亮度，结束后恢复 | 亮屏充电、刷视频、看文档 | 这是体感最直接的一项，因为屏幕本来就是耗电大户之一 |
| `低电量模式` | 启用 iOS 自带的 Low Power Mode | 一边补电一边想尽量少掉电 | Apple 说明它会降低背景活动、降低亮度、限制部分高刷 / 后台行为；体验会变保守 |

当前实现说明：

- 亮度会记录并恢复到充电前的值，自动亮度状态也会一并恢复。
- `飞行模式 / Wi-Fi / 蓝牙 / 低电量模式` 结束时会按当前实现尝试恢复到预设状态，而不是完整缓存每一项原始状态。
- 所以这部分更适合“临时急充”，不适合你长期忘着开。

更形象一点：

> 加速充电像是你给手机做“减重训练”。
> 不是让水龙头出水更猛，而是让桶边上少漏水。

### 停充控制

这是整个项目最核心的一组设置。

#### `智能停充`

- 作用：停充时优先走 `PredictiveChargingInhibit` 路径，而不是直接把 `IsCharging` 改成 `NO`
- 两条路径的区别不是“能不能停充”，而是“怎么表达停充”：
- `PredictiveChargingInhibit` 更像“保持外部供电会话存在，但抑制继续往电池里充”
- 传统 `IsCharging` 路径更像“直接把正在充电这个状态关掉”
- 在支持较好的设备上，前者通常更接近系统自己的充电抑制语义，所以状态会更干净，也更像 Apple 原生行为
- 该功能现在默认开启；如果系统拒绝写入，或停充命令发出后一段时间仍未进入抑制态，daemon 会自动回退到传统 `IsCharging` 停充路径

适合：

- 希望停充行为更贴近系统原生的充电抑制语义
- 设备与系统版本对 `PredictiveChargingInhibit` 路径支持较好
- 想直接用更推荐的默认停充路径，不想自己判断该不该开

资源开销：

- 常驻开销很低
- 主要发生在状态切换时写一次充电属性
- 不会因为你打开它就额外启动高频轮询

#### `停充时启用禁流`

- 作用：达到停充条件后，不只是“不给电池充电”，而是进一步让设备尽量不再从外部继续进流
- 这会让机器更像“插着线，但当前负载主要自己扛”

适合：

- 你非常明确知道自己想要更激进的停充效果
- 你愿意接受插电时电量继续自然下滑

不适合：

- 想稳定守在某个电量附近的用户
- 想配合 `插电保持` 长期开启的用户

为什么不建议和 `插电保持` 常开：

- `禁流` 的思路是“尽量不让电进来”
- `插电保持` 的思路是“在目标附近少量、按需补电”
- 一个像关水阀，一个像恒温补水，方向本来就相反

资源开销：

- daemon/CPU 开销很低
- 但行为代价很高，因为设备会更依赖电池自身放电去扛当前负载

#### `插电保持`

这是当前最值得理解的功能。

它的逻辑可以直接类比空调或冰箱的回差控制：

- `停止充电目标` = 设定温度
- `保持带宽` = 回差
- 到点就停
- 低于下边界再补

也就是说，它追求的不是“永远钉死在 50%”，而是“尽量围绕 50% 这个目标小范围波动”。

举例：

- `停止充电 = 50%`
- `保持带宽 = 2%`

那么大致会这样工作：

- 到 `50%` 停
- 在 `48% ~ 50%` 之间观察
- 掉到 `48%` 或检测到持续放电趋势时恢复补电

资源开销：

- 这是高级设置里最主要的连续后台开销来源
- 它会启动一个周期性定时器，并按当前策略定期重评估电池状态
- 但开销仍然属于轻量级，不是高 CPU、重网络、重磁盘任务

#### `保持带宽`

- 范围：`1% ~ 10%`
- 作用：决定目标电量下方允许回落多少再恢复补电

怎么理解：

- 带宽越小：更贴着目标，但更容易频繁补电
- 带宽越大：补电次数更少，但电量波动更明显

建议起点：

- 轻负载办公：`2% ~ 3%`
- 中高负载或无线充：`3% ~ 4%`
- 想观察系统先怎么跑：先从 `2%` 开始

资源开销：

- 带宽本身不增加额外模块
- 但带宽越小，状态来回切换和补电动作通常会更频繁

#### `保持策略`

`保持策略` 不改变目标电量本身，它改变的是：

- daemon 多久检查一次 hold 状态
- 是否允许“还没掉到下边界，就因为持续放电趋势而提前补电”
- 在自适应模式下，运行时如何自动切换策略

源码当前实现如下：

| 策略 | 轮询间隔 | 提前补电规则 | 体感倾向 | 后台开销 |
| --- | --- | --- | --- | --- |
| `平衡` | `15` 秒 | 连续 `2` 次检测到明显放电趋势后，可提前补电 | 不太容易掉电，也不过分积极 | 低 |
| `偏向外接供电` | `10` 秒 | 连续 `1` 次明显放电即可提前补电 | 更努力让充电器扛住负载，减少你看到电量下滑 | 固定策略里最高 |
| `偏向减少循环` | `20` 秒 | 默认不做“提前补电” | 更愿意等掉到下边界再补，减少目标附近小来回 | 固定策略里最低 |
| `智能自适应` | 运行时在以上三档间切换 | 会综合平均电流、适配器功率、温度、无线充状态决定 | 自动挡，适合负载变化大的用户 | 低到中 |

更直白一点：

- `平衡`：像普通家用车的 `D` 挡
- `偏向外接供电`：像想让发动机更积极介入，尽量别掉速
- `偏向减少循环`：像尽量少踩油门，允许速度有点波动
- `智能自适应`：自动看路况换挡

#### `智能自适应` 到底看什么

项目当前的第一版自适应逻辑，主要依据这些信号：

- 最近 `5` 次电流样本的平均值
- 适配器功率
- 是否无线充
- 当前温度是否已经接近你设定的高温上限

当前关键规则：

- 平均电流持续更偏负时，会认为设备在边充边吃负载
- 只有当适配器功率未知，或者 `>= 12W` 时，才更愿意进入 `偏向外接供电`
- 如果正在无线充，会更保守
- 如果当前温度已经接近高温停充阈值 `1.5°C` 以内，也会更保守
- 为了避免来回抖动，策略切换后至少要有 `60` 秒最小驻留时间

当前阈值说明：

- 高负载进入阈值：平均电流大致 `<= -450 mA`
- 高负载退出阈值：大致 `<= -260 mA`
- 中负载进入阈值：大致 `<= -180 mA`
- 中负载退出阈值：大致 `<= -100 mA`

这里的负号可以简单理解成：设备正在从电池侧“拿电”。

所以你会看到一种很合理的现象：

- 刷网页、聊天、待机：更偏 `偏向减少循环`
- 看视频、轻度导航：更偏 `平衡`
- 游戏、热点、长时间录屏：更偏 `偏向外接供电`
- 无线充或临近高温阈值：自动转保守

资源开销：

- 比固定策略多一点样本统计和运行时策略切换记录
- 但依然是轻量级
- 事件写入只在关键切换时发生，不是每次轮询都写磁盘

### 系统优化充电

Apple 的 `Optimized Battery Charging` / `Charge Limit` 本意，是减少设备长时间处在高电量和满电状态的时间，以改善电池寿命。

ChargeLimiter 这里要做的，不是简单说“它好”或“它坏”，而是解决一个现实问题：

> 当系统自己的优化充电，和你手动设定的停充/保持逻辑同时存在时，两个控制器可能会互相打架。

#### `永久停用系统优化充电`

- 作用：直接关闭系统优化充电
- 效果最彻底
- 代价也最大，因为你把 Apple 原生那套长期学习和夜间充电优化一起关掉了

适合：

- 你完全决定只按 ChargeLimiter 的策略运行
- 你不想再让系统原生充电优化介入

不适合：

- 你只是想在 `插电保持` 期间临时避免冲突

#### `插电保持时临时停用`

- 作用：只有在 `hold / hold_recharge / stopped / temp_paused / no_inflow` 这些需要 ChargeLimiter 接管的状态里，临时停用系统优化充电
- 退出这些状态后，再尝试恢复原本状态

当前实现已经做了这些保护：

- 进入接管前记录原始系统状态
- 生成一轮协调会话 ID
- daemon 重启后，会先按当前电池真实状态重算，再决定恢复还是继续接管
- 如果系统状态被外部改变，也会结束当前接管会话，避免误恢复

这是更推荐的默认做法。

一句话理解：

- `永久停用`：把系统这位“副驾驶”永久请下车
- `临时停用`：只有你需要手动接管方向盘时，先让副驾驶别抢方向

资源开销：

- 几乎可以忽略
- 主要发生在进入/退出接管状态，以及 daemon 启动恢复时
- 不是高频后台任务

实战建议：

- 长期插电保电量：优先用 `插电保持时临时停用`
- 只有在你明确不想要系统优化充电时，再考虑 `永久停用`

### 调试与观测

这部分不会直接改变充电行为，但它决定了你能不能真正看懂当前策略。

如果你只看一个页面，我最建议你看 `策略诊断`。

#### 策略运行时

| 项目 | 你能从这里看到什么 |
| --- | --- |
| `守护策略` | 当前处于 `正在充电 / 已停止充电 / 插电保持中 / 插电保持中·补电 / 温控暂停 / 已禁流` 哪一种 |
| `当前状态原因` | 为什么会变成现在这个状态，例如到达保持目标、低于下边界、温度过高、满充窗口、持续放电趋势 |
| `最近策略切换时间 / 原因` | 最近一次切换发生在什么时候、为什么切 |
| `充电命令 / 最近充电命令时间` | daemon 最近有没有主动下发“开始充电 / 停止充电” |
| `系统停充抑制` | 当前是否处于系统的停充抑制路径 |
| `系统优化充电` | 系统优化充电当前是启用、关闭、满充窗口还是已临时停用 |
| `由本工具接管` | 当前这次临时停用是不是 ChargeLimiter 自己发起的 |
| `接管前系统状态` | 进入这轮接管前，系统原本是什么状态 |
| `协调会话 / 接管开始时间` | 这一轮 Smart Charge 协调的唯一标识与起始时间 |
| `最近禁流/恢复时间` | 最近一次禁流或解除禁流是什么时候 |

#### 保持诊断

这是理解 `插电保持` 的关键。

| 项目 | 含义 |
| --- | --- |
| `保持策略` | 你在设置页里选的策略 |
| `当前生效策略` | 运行时真正正在用的策略；在 `智能自适应` 下尤其重要 |
| `自适应负载等级` | 当前被判断为 `低负载 / 中负载 / 高负载 / 温控保护 / 无线充保护 / 固定策略` 中的哪一种 |
| `近几次平均电流` | 自适应逻辑最近参考的平均电流 |
| `保持目标` | 当前 hold 目标，一般就是你的 `停止充电` 目标 |
| `保持带宽` | 当前回差宽度 |
| `保持下边界` | 真正触发补电的下边界 |
| `持续放电计数` | 当前已经连续多少次看到明显放电趋势 |
| `轮询间隔` | 当前 hold 定时器多久跑一次 |
| `提前补电辅助` | 当前策略是否允许“还没掉到底线就先补” |

如果你看到：

- `当前生效策略 = 偏向外接供电`
- `自适应负载等级 = 高负载`
- `当前状态原因 = 检测到持续放电趋势，提前补电`

那就说明系统判断你这会儿负载比较重，正在更积极地保电量。

#### 实时信号

这一组是最底层的事实输入：

- `当前电量`
- `电池温度`
- `电池电流`
- `瞬时电流`
- `是否正在充电`
- `是否连接外部电源`
- `系统判定可充电`

如果策略结果和你预期不一致，先看这一组，不要先怀疑策略本身。

#### 供电环境

这一组帮助你理解“为什么同样的策略，这次和上次表现不一样”：

- `适配器`
- `适配器功率`
- `充电方式`

比如：

- 同样是 `偏向外接供电`
- 20W 有线 和 5W 无线

跑出来的效果本来就不应该一样。

#### 最近策略切换 / 长时间事件时间线

这两组的区别：

- `最近策略切换`：更像最近几步怎么走的“短历史”
- `长时间事件时间线`：更像可复盘、可导出的“长历史”

当前策略事件会持久化到独立 `sqlite` 表里，所以 daemon 中途重启后，最近一段历史也尽量不会丢。

#### 导出与校准

| 项目 | 作用 |
| --- | --- |
| `复制诊断摘要` | 把当前关键状态打包成一段文本，适合发给别人排障 |
| `导出事件时间线` | 导出最近的长时间策略事件，适合做复盘 |
| `复制长测校准模板` | 把当前设备、系统版本和关键参数整理成测试模板 |

---

### 满充计划

这项功能适合“平时不想长时间高电量，但偶尔还是想有一次完整满充”的人。

它不是永久放开上限，而是定期创建一个“临时豁免窗口”。

#### `启用满充计划`

- 开启后，设备会每隔一段时间进入一次“临时解除上限”的窗口
- 在窗口内，上限会被临时视为 `100%`
- 但温度控制仍然继续生效

#### `每隔天数`

- 范围：`1 ~ 90` 天
- 表示多久执行一次满充窗口

例子：

- `7` 天：每周一次
- `30` 天：每月一次

#### `开始时间`

- 表示一天中的哪个时刻开始放开上限

适合安排在：

- 凌晨
- 睡前
- 出门前

#### `持续时长`

- 范围：`1 ~ 12` 小时
- 时间越长，越容易真正充得更高
- 时间越短，越像一次轻量“放行”

资源开销：

- 常驻开销极低
- 主要就是一个定时边界检查
- 远低于 `插电保持`

---

### 限流控制

这项设置非常容易被误解。

它并不是“直接对 PMIC 下发一个固定安培数”。

当前项目里的 `限流控制`，本质上是：

- 在充电时切换到更保守的热状态模拟
- 借此让系统整体倾向于更低功耗、更保守的充电行为
- 结果通常表现为充电电流 / 电压更小、温升更低，但前台性能也可能更保守

#### `限流等级`

可选：

- `关闭`
- `正常`
- `轻度`
- `中度`
- `重度`

它的理解方式可以很简单：

- 档位越高，系统越像在说“现在我不想太激进”
- 结果通常就是：更凉、更稳，但也更慢

适合：

- 发热比较明显的边充边用
- 无线充
- 夏天、车内、高环境温度

不适合：

- 你就想尽快把电补进去
- 你当前更在意性能而不是温度

资源开销：

- daemon 本身开销很低
- 真正的代价是系统性能 / 充电速度上的让步

---

### 高温模拟 (Powercuff)

这一组和 `限流控制` 强相关，但作用范围更广。

可以把它理解成：

> 你主动告诉系统“假设现在热一点”，让系统提前进入更保守的功耗/性能策略。

#### `默认等级`

- 作用：设置非充电状态下默认使用的高温模拟等级
- 如果没有启用 `限流控制`，它主要影响平时系统整体的保守程度
- 如果启用了 `限流控制` 且没有锁定等级，充电时会临时切到 `限流等级`，停充后再切回这里的默认等级

#### `锁定等级`

- 作用：防止 daemon 在“充电 / 停充”之间自动来回切换热模拟等级
- 开启后，系统会尽量一直维持你手动设定的默认等级

这个开关什么时候有用：

- 你在做性能 / 发热测试，想固定一个热状态
- 你不想让 `限流控制` 在充电状态变化时自动接管热模拟

#### 各档怎么理解

下面的“效果”是基于项目当前档位映射和 Apple Thermal State 文档做出的解释。Apple 对热状态给的是行为定义，不是固定的“必然降到多少 MHz、必然限到多少 mA”；实际强度会随机型和系统版本变化。

| 档位 | 项目内部值 | 可近似对应的热状态语义 | 可能的体感代价 |
| --- | --- | --- | --- |
| `关闭` | `off` | 不主动模拟高温 | 无额外代价 |
| `正常` | `nominal` | 正常热状态 | 基本没有可见影响 |
| `轻度` | `light` | 接近 Apple 文档里的 `Fair` | 轻微保守，通常适合长期轻限流 |
| `中度` | `moderate` | 接近 `Serious` | 性能可能已有明显影响，适合发热更重的场景 |
| `重度` | `heavy` | 接近 `Critical` | 系统会非常保守，只适合测试或特殊场景 |

Apple 对热状态的官方定义重点是：

- `Fair`：热量轻度升高，能耗升高，应用可以开始主动降载
- `Serious`：热量明显升高，系统可能已经开始采取对策
- `Critical`：设备需要尽快降温

所以别把 `Powercuff` 理解成“免费降温按钮”。

它更像：

- 用性能和系统激进程度
- 去换更低的发热和更稳的供电环境

### 其他

#### `重置所有设置`

- 把所有配置恢复到默认值
- 适合排障、重新调参、或者你已经忘了自己之前改过什么

默认值要点：

- `停止充电 = 80%`
- `开始充电 = 20%`
- `智能停充 = 开`
- `保持带宽 = 2%`
- `保持策略 = 平衡`
- `插电保持时临时停用系统优化充电 = 开`
- `限流等级 = 中度`
- `Powercuff 默认等级 = 关闭`
- `满充计划 = 关闭`

## 资源开销总览

下面这张表分成两种“开销”来看：

- `后台开销`：对 daemon 的常驻轮询、CPU、定时器、事件写入影响
- `行为代价`：对性能、联网、通知、体感、充电速度的影响

| 功能 / 模式 | 后台开销 | 行为代价 | 说明 |
| --- | --- | --- | --- |
| `智能停充` | 很低 | 很低 | 默认开启；优先走 `PredictiveChargingInhibit`，不生效时自动回退 |
| `停充时启用禁流` | 很低 | 高 | CPU 不高，但设备会更依赖电池扛当前负载 |
| `插电保持 - 偏向减少循环` | 低 | 低到中 | `20` 秒轮询，最省后台，也最保守 |
| `插电保持 - 平衡` | 低 | 低到中 | `15` 秒轮询，默认最均衡 |
| `插电保持 - 偏向外接供电` | 低到中 | 中 | `10` 秒轮询，最积极补电 |
| `插电保持 - 智能自适应` | 低到中 | 低到中 | 额外做平均电流与策略切换判断，但仍属轻量 |
| `系统优化充电临时协调` | 近乎忽略 | 很低 | 主要在进入/退出接管状态时动作 |
| `满充计划` | 近乎忽略 | 低 | 只有定时边界检查 |
| `限流控制` | 很低 | 中到高 | 不是 daemon 吃资源，而是系统主动变保守 |
| `Powercuff 默认等级` | 很低 | 取决于档位 | 档位越高，性能 / 充电激进程度越保守 |
| `策略诊断 / 导出` | 按需 | 很低 | 只有查看或导出时才有额外 UI / 文本处理 |

一句话总结：

- **真正有连续后台开销的，主要是 `插电保持`。**
- **真正有明显体验代价的，主要是 `禁流 / 限流 / Powercuff / 加速充电的联网类开关`。**

## 典型场景推荐

### 场景 1：办公桌长期插电

目标：

- 长时间插着线办公
- 不想总是 100%
- 更想减少循环和热量

建议：

- `停止充电 = 50% ~ 60%`
- 打开 `插电保持`
- `保持带宽 = 2%`
- `保持策略 = 偏向减少循环` 或 `智能自适应`
- 打开 `插电保持时临时停用系统优化充电`
- 夏天可再考虑 `限流等级 = 轻度`

形象理解：

> 这套更像“桌面驻留模式”。
> 电池不是主角，而是一个维持稳定的小水箱。

### 场景 2：游戏 / 导航 / 热点 / 录屏

目标：

- 插电时尽量别一边玩一边掉电太快

建议：

- `停止充电 = 70% ~ 80%`
- 打开 `插电保持`
- `保持带宽 = 3%`
- `保持策略 = 偏向外接供电` 或 `智能自适应`
- 不要开 `停充时启用禁流`
- 如果发热明显，再尝试 `限流等级 = 轻度 / 中度`

形象理解：

> 这套更像“充电器先顶上，电池少背锅”。

### 场景 3：床头夜充，但偶尔还是想满电出门

目标：

- 平时别总满电
- 但每隔一段时间允许一次更高电量

建议：

- 平时 `停止充电 = 80%`
- 开 `满充计划`
- `每隔天数 = 7`
- `开始时间 = 02:00`
- `持续时长 = 4 小时`

这更适合有固定作息的人。

### 场景 4：无线充 + 高温环境

目标：

- 优先稳和凉，不追求最快

建议：

- `保持策略 = 智能自适应`
- `保持带宽 = 3% ~ 4%`
- `限流等级 = 轻度`
- 必要时打开温度控制
- 不建议用 `偏向外接供电`

因为 Apple 官方也明确提到：无线充本身就是设备更容易变暖的场景之一。[参考资料](#参考资料与依据)

## 排障建议

如果你遇到“为什么这次没按我想的充”：

1. 先看 `策略诊断`
2. 再看 `实时信号`
3. 再看 `供电环境`
4. 最后再调参数

优先调整顺序建议：

1. 先调 `保持带宽`
2. 再调 `保持策略`
3. 再看要不要改 `温度控制`
4. 最后才考虑 `禁流 / 限流 / Powercuff`

如果要长期验证，建议配合 [docs/真机长测与阈值校准.md](docs/真机长测与阈值校准.md) 一起用。
