# 配置日志级别设置设计

## 背景

ChargeLimiter 的 `aldente.log` 当前由 `NSFileErrorLog` 集中写入。为定位 Relaxin roothide 路径回归，近期加入了 `path_init`、`daemon_entry`、`daemon_paths`、`daemon_privilege` 等启动诊断。它们对故障定位有价值，但在正常运行时会重复写入，降低日志信噪比。

## 目标

- 在高级设置的“调试与观测”区域增加“日志级别”选择。
- 提供两个级别：`标准`（默认）和 `仅错误`。
- 默认日志保留错误、严重故障、daemon 启动成功摘要和端口监听结果。
- `仅错误` 时只写错误、严重故障和启动失败事件。
- 由文件日志集中入口统一过滤，避免逐条删除现有诊断调用。
- App 和 daemon 使用同一个共享配置键，并在配置变更后保持一致。
- 继续保留完整诊断报告中的路径、权限、文件状态和配置加载信息。

## 非目标

- 不增加独立的“详细诊断日志”开关。
- 不过滤 `NSLog2`/`os_log` 系统日志；设置只控制 `aldente.log` 文件。
- 不记录配置键和值，不重置或迁移用户配置。
- 不改变 rootful、rootless、roothide 或 TrollStore 的路径策略。

## 用户界面

在 `CLAdvancedSettingsViewController` 的“调试与观测”卡片中增加 picker 行：

- 标题：`日志级别`
- `标准`：错误 + 严重故障 + 简短启动成功摘要
- `仅错误`：错误 + 严重故障

现有 picker 的 action sheet 交互和本地化机制复用。缺少配置键时显示并写入 `标准`，保证旧版本升级后行为不变。

## 配置与数据流

使用共享 plist 键 `log_level`，值为稳定字符串：

- `normal`：标准
- `error`：仅错误

设置页通过现有共享配置写入路径保存。写入成功后刷新 App 进程内的文件日志级别，并通过现有 daemon 配置重载路径刷新 daemon 进程内缓存；重载失败仍保留原有设置保存结果和错误提示语义。进程缓存无法刷新时回退到 `normal`，避免隐藏错误。

## 文件日志分级

新增显式文件日志级别入口，集中由 `NSFileLogWithArguments` 判断：

- `error`：错误、严重故障、启动失败、配置写入/回读失败、端口绑定失败。
- `normal`：上述全部，加上一次性的启动摘要和 `listen_ready` 成功事件。

近期为路径排查增加的高频细节（完整 `path_init` 路径、`daemon_paths`、uid/euid/csops 细节）不进入默认文件日志；完整诊断报告仍从进程接口读取这些元数据。错误日志中的配置键和值继续禁止输出。日志文件默认只输出稳定路径标识，不要求暴露随机 `.jbroot-*` token。

`NSFileErrorLog` 保持兼容并继续表示重要错误；成功/信息型启动行迁移到新的信息级入口。`NSLog2` 仍按现有方式写入系统统一日志，不受本设置过滤。

## 兼容与故障处理

- 未知或缺失的 `log_level` 值按 `normal` 处理。
- 设置保存失败时沿用现有 rollback 和 `Save Failed` 行为。
- daemon 无法重载配置时不改变日志级别缓存，继续使用上一次有效级别；进程重启后重新从共享 plist读取。
- 日志轮转上限保持现有 256 KiB，不新增清理或权限修复行为。

## 验收标准

1. 高级设置显示“日志级别”，默认选中“标准”。
2. 切换到“仅错误”后，新的 `aldente.log` 不再追加 `daemon_paths`、uid/euid 等信息型启动行，但错误和启动失败仍会写入。
3. 切换回“标准”后，`listen_ready` 和简短启动摘要可见。
4. App 重启、daemon 重启后级别保持一致。
5. 完整诊断报告仍能显示配置路径一致性、文件元数据、最近写入阶段和 daemon 加载键数。
6. rootful、rootless、roothide 三套 scheme 编译通过，现有设置持久化测试不回归。
